Step 3

제작 콘텐츠

유형참여 흐름끝나고 남는 데이터주 목적 / 기간
A. 참여 유도
룰렛, 럭키드로우현장, 온라인 QR 스캔 → 룰렛 1회 → 즉시 쿠폰 발급 → 매장 사용 시 결제 매칭 참여 ID, 스캔 지점, 당첨 등급, 쿠폰 코드, 사용 시각, 매장 판매기본형 1~2주
퀴즈, OX현장, 온라인 진입 → 3~5문항 → 결과와 해설 → 보상 또는 공유 참여 ID, 문항별 정답률, 완주 여부, 소요 시간 인지, 판매기본형 1~2주
유형 테스트현장, 온라인 문항 6~10개 → 유형 판정 → 결과 카드 → 저장, 전송(동의 지점) 참여 ID, 유형 결과 = 세그먼트, 동의 항목, 연락처 데이터기본형 1~2주
인증 이벤트현장, 온라인 구매, 방문 → 사진 업로드 → 검수 → 보상 참여 ID, 인증 이미지, 구매 금액, 매장, 승인 상태 판매기본형 1~2주
B. 브랜드 각인, 체류시간 확보
브랜드 미니게임현장, 온라인 진입 → 튜토리얼 → 플레이 → 점수, 랭킹 → 재도전 참여 ID, 점수, 시도 횟수, 재참여율, 단계별 이탈 인지커스텀형 3~5주
AR 필터, 얼굴 인식현장, 온라인 카메라 권한 → 필터 적용 → 촬영 → 저장, 공유 참여 ID, 필터 종류, 촬영, 저장 수, 공유 채널 인지AI/AR형 4~6주
포토부스, 키오스크현장 설치형 촬영 → 브랜드 프레임 합성 → 출력 → 링크, 문자 전송(동의 지점) 참여 ID, 촬영 시각, 부스 위치, 전송 연락처, 동의 항목 데이터AI/AR형 4~6주
AI 이미지 변환현장, 온라인 사진 업로드 → AI 변환 → 결과 확인 → 저장, 공유 참여 ID, 선택한 스타일, 변환, 저장 수, 재시도 횟수 인지AI/AR형 4~6주
C. 재방문 유도
스탬프 투어현장 지점 QR 스캔 ×N → 스탬프 적립 → 전체 완주 → 보상 참여 ID, 지점별 스캔 시각, 도달 깊이, 완주율 데이터기본형 1~2주
출석체크온라인 최초 참여 → 일자별 출석 → 누적 보상 → 최종 보상 참여 ID, 출석 일자, 연속 일수, 이탈 시점 데이터기본형 1~2주
추천코드, 리퍼럴온라인 참여 → 고유 코드 발급 → 지인 참여 → 양쪽 보상 추천인/피추천인 ID, 코드별 유입 수, 바이럴 계수 K 인지기본형 1~2주

어떤 유형이든 기본으로 들어가는 것

  • 앱 설치 없이 QR 한 번으로 진입하는 웹 구조 — 설치를 요구하면 진입에서 대부분 이탈합니다
  • 참여 시점 방문객 ID 발급 — 이 키가 없으면 이후 어떤 측정도 성립하지 않습니다
  • 참여 로그 자동 수집 — 스캔, 시작, 단계 통과, 완주, 동의, 보상 수령
  • 모바일 반응형과 실기기 QA — iOS Safari, Android Chrome, 카카오톡, 인스타그램 인앱 브라우저
  • 종료 시 원본 로그와 세그먼트를 브랜드에 이관 — 리포트만 남기지 않습니다

Step 5

예산은 이렇게 정해집니다

정확한 금액은 범위가 정해져야 나옵니다. 대신 무엇이 예산을 움직이는지를 먼저 공개합니다. 아래 항목 중 몇 개가 켜지는지에 따라 같은 “미니게임 하나”도 배 이상 차이가 납니다.

예산을 움직이는 항목왜 올라가나줄이는 방법
게임 로직을 새로 설계하는가 정해진 로직(룰렛, 스크래치, 퀴즈)에 브랜드를 입히는 것과, 규칙을 새로 만드는 것은 기획, 개발 공수가 다릅니다 첫 캠페인은 기본형으로 검증하고, 반응을 본 뒤 커스텀으로 갑니다
AI/AR 이 들어가는가 이미지 인식, AR 인터랙션은 구현보다 인식 정확도 검증에 시간이 듭니다. 실패 케이스를 얼마나 잡느냐가 곧 비용입니다 인식 대상을 하나로 좁힙니다. 대상이 늘수록 검증량이 곱으로 늘어납니다
본인인증이 필요한가 주류, 연령 제한 업종은 PASS 등 인증 연동이 필수입니다. 외부 서비스 연동과 실패 처리 설계가 붙습니다 업종상 불가피하면 줄일 수 없습니다. 대신 그 대가로 추정 없는 연령, 성별 데이터를 얻습니다
기프티콘, 경품을 자동 발송하는가 발송 API 연동, 재고, 당첨 확률 관리, 실패 재발송까지 설계해야 합니다 수동 발송으로 시작하고, 규모가 커지면 자동화합니다
기존 시스템과 연동하는가 CRM, CDP, POS, 회원 시스템 연동은 상대 시스템 스펙에 좌우됩니다. 저희 쪽 공수보다 협의, 테스트 기간이 깁니다 1차에는 저희 대시보드로 운영하고, 종료 후 데이터셋을 이관합니다
동시 접속 규모가 큰가 실시간 추첨, 중계처럼 피크가 몰리는 구조는 서버 용량 설계와 부하 테스트가 별도로 필요합니다 참여 시간을 분산하는 설계(응모번호 발급 후 추첨)로 피크를 낮춥니다
디자인 에셋을 새로 만드는가 캐릭터, 일러스트, 사운드를 새로 제작하면 그만큼 붙습니다 보유 브랜드 에셋을 재사용합니다. 게임 화면은 대부분 기존 에셋으로 구성 가능합니다
현장 운영이 포함되는가 인력, 기기 대여(태블릿, 포토부스), 설치가 들어가면 제작비와 별개로 운영비가 생깁니다 운영은 브랜드 측 인력으로 하고 저희는 매뉴얼, 모니터링만 맡는 구성도 가능합니다

견적을 빨리 받는 방법

  • 목적 하나 — 인지 / 판매 / 데이터 확보 중 무엇인지
  • 시기와 기간 — 언제, 며칠 또는 몇 주간 운영하는지
  • 예상 참여 규모 — 하루 몇 명 수준인지
  • 위 표에서 반드시 필요한 항목이 무엇인지

이 네 가지만 알려주시면 범위와 개략 예산을 먼저 정리해 드립니다. 정확한 견적서는 범위 확정 후에 드립니다.
